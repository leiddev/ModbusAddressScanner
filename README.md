# ModbusAddressScanner

🙏 大部分布局及逻辑代码由豆包（https://www.doubao.com/）生成，其中使用了 NModbus4 NuGet 包。

ModbusAddressScanner 是一个用于扫描和识别 Modbus 设备地址的工具，目前支持 Modbus RTU。
（Modbus TCP 尚未实现，仅保留了后续扩展的可能。）

## 功能特点

- 自动扫描 Modbus RTU 从机地址范围 **1~247**，可勾选要尝试的读功能码
  （`01` 线圈 / `02` 离散输入 / `03` 保持寄存器 / `04` 输入寄存器，默认只勾选 `03`）。
  每个地址依次尝试已勾选的功能码，只要其中一个有响应（包括从机返回的异常响应）
  即认为找到了从机地址，并**继续扫描剩余地址**，可一次列出总线上所有在线从机。
- 支持自定义串口、波特率、数据位、停止位和校验方式。
- 支持手动指定**读超时时间**（毫秒），留空则按波特率自动估算。
- 开始扫描时会在日志中输出**预计扫描时间**，便于判断需要等待多久。
- 用户界面简洁易用，适合快速定位 Modbus 设备。

## 使用方法

1. 选择串口及串口参数（波特率、数据位、停止位、校验位），需与目标设备保持一致。
2. 填写**寄存器起始地址**和**寄存器数量**（该地址与数量会同时用于所有已勾选的功能码）：
   - 起始地址填写 **PDU 偏移量（从 0 开始）**，即 40001 应填 `0`、40101 应填 `100`；
     取值范围 0~65535，数量取值范围 1~125（功能码 0x03/0x04 的协议上限）。
   - 建议填写目标设备确实存在的寄存器，否则设备可能以异常响应作答（见下）。
3. 在「扫描控制」中勾选要尝试的**读功能码**，至少勾选一个，默认只勾选 `03`：
   - `01` 线圈（Read Coils）、`02` 离散输入（Read Discrete Inputs）、
     `03` 保持寄存器（Read Holding Registers）、`04` 输入寄存器（Read Input Registers）。
   - 勾选越多越容易发现设备，但无响应地址的等待时间会成倍增加，详见「性能说明」。
4. 可选：填写**读超时(ms)**。留空（占位符显示「自动」）表示按波特率自动计算，
   手动填写时取值范围 1~60000 毫秒。若手动值低于当前波特率的建议值，
   日志会给出提醒，因为响应较慢的从机可能被漏掉。
5. 点击「开始」进行扫描，点击「停止」可随时中断。

## 扫描行为说明

- 扫描按地址从小到大**完整扫描 1~247 全部地址，发现从机后不会提前停止**，
  期间每发现一个地址即时记录日志；全部扫描结束后统一汇总，弹窗列出所有找到的地址。
  不统计单次响应时间（仅记录本次扫描总耗时）。
- 扫描耗时与是否找到从机无关，总会扫完 247 个地址（除非手动停止）。
- 地址 0 为广播地址（从机按规范不应答），248~255 为保留地址，因此不参与扫描。
- 每个地址会**按 `01` → `02` → `03` → `04` 的顺序依次尝试已勾选的功能码**，
  命中（读到数据或收到异常响应）后立即停止对该地址的尝试，接着扫描下一个地址。
- 判定「有响应」包括两种情况：
  1. 正常读取到位数据或字数据；
  2. 从机返回**异常响应**（功能码 | 0x80，如异常码 0x01 表示不支持该功能码、
     0x02 表示非法数据地址）。异常响应是一个带合法 CRC 的完整应答，
     说明该从机真实存在，只是拒绝了本次请求。
     此时日志会记录 `✅ 地址 X 存在（功能码 0X 返回异常码 0x0X）`。
- 只有读超时、CRC 校验失败等情况才判定为无响应。
- 汇总结果会标注每个地址命中的功能码，例如 `20（功能码03）`。

> 提示：若扫描结果提示「未找到有效地址」，请优先确认寄存器起始地址是否为目标设备
> 实际存在的地址，以及串口参数、接线（A/B 线）是否正确。

## 性能说明

- 读超时默认按波特率自动估算（最坏 256 字节帧长 × 11 位 + 200ms 处理余量，
  下限 300ms、上限 2000ms）：9600 bps 为 493ms，19200 bps 为 347ms，
  38400 bps 及以上为 300ms。
- 手动填写读超时后即以该值为准，上述自动估算不再生效；调小可加快扫描，
  但低于从机的实际响应时间会导致漏报。
- 每次开始扫描时，日志会先输出**预计扫描时间**（按最坏情况估算的上界），例如：
  `预计扫描时间：最坏约 2 分 15 秒（247 个地址 × 读超时 493 ms × 1 个功能码，找到设备的地址会明显更快）`
- 估算公式为 `247 × (读超时 + 55ms 固定开销) × 勾选的功能码数量`。
  55ms 是一次探测中除读超时以外的固定开销（发送请求、串口读写、CRC 校验等），
  由整轮实测校准得出：9600bps / 读超时 493ms 下 247 个地址实测 135.3 秒，
  与公式估算的 135.4 秒基本一致。
- 按自动读超时估算，最坏情况（总线上没有任何设备应答）扫描耗时约为：
  9600 bps（493ms）**2 分 15 秒**、19200 bps（347ms）**1 分 39 秒**、
  38400 bps 及以上（300ms）**1 分 28 秒**。
- **勾选多个功能码会成倍增加耗时**：无响应的地址需要对每个功能码各等一轮读超时，
  最坏耗时约为单功能码的 N 倍。例如 9600 bps 下勾选 4 个功能码最坏约 **9 分 1 秒**，
  只勾选 `03` 时约 **2 分 15 秒**。建议先只勾选 `03` 快速扫一遍，没找到设备时再增加其他功能码。
- 扫描期间每 10 个地址输出一次进度日志（247 个地址共 24 行），避免逐条刷屏拖慢界面。

## 已知限制

- 汇总结果仅显示在日志文本框与结束弹窗中，界面上没有独立的地址列表控件，结果也不落盘保存。
- 起始地址与数量由所有已勾选的功能码共用，无法为不同功能码分别指定。
- 数量上限固定为 125（按 `03`/`04` 的协议上限），因此无法用 `01`/`02` 一次读取超过
  125 个线圈；不过扫描只关心「是否有响应」，数量填 1 通常即可。
- 尚未支持 Modbus TCP。

## 依赖与目标框架

| 包 | 版本 | 说明 |
| --- | --- | --- |
| [NModbus4](https://www.nuget.org/packages/NModbus4) | 2.1.0 | Modbus 主站实现，仅提供 .NET Framework 资产，构建时会出现 NU1701 回退告警 |
| [System.IO.Ports](https://www.nuget.org/packages/System.IO.Ports) | 6.0.0 | .NET 6 下的串口实现 |

- 目标框架：`net6.0-windows`。**.NET 6 已于 2024-11 停止支持**，构建会出现 NETSDK1138
  告警且不再获得安全更新，建议升级到 .NET 8。
- 长期维护建议迁移到官方后继包 **NModbus 3.x**（提供 netstandard2.0 资产，可被 .NET 6+ 原生引用）。

- .NET 6 Desktop Runtime 或更高版本的 .NET Desktop Runtime
