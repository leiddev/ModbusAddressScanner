# ModbusAddressScanner

🙏 大部分布局及逻辑代码由豆包（https://www.doubao.com/）生成，其中使用了 NModbus4 NuGet 包。

ModbusAddressScanner 是一个用于扫描和识别 Modbus 设备地址的工具，目前支持 Modbus RTU。
（Modbus TCP 尚未实现，仅保留了后续扩展的可能。）

## 功能特点

- 自动扫描 Modbus RTU 从机地址范围 **1~247**，使用读取保持寄存器功能码（0x03）。
  只要该地址对指令有响应（包括从机返回的异常响应）即认为找到了从机地址。
- 支持自定义串口、波特率、数据位、停止位和校验方式。
- 用户界面简洁易用，适合快速定位 Modbus 设备。

## 使用方法

1. 选择串口及串口参数（波特率、数据位、停止位、校验位），需与目标设备保持一致。
2. 填写**寄存器起始地址**和**寄存器数量**：
   - 起始地址填写 **PDU 偏移量（从 0 开始）**，即 40001 应填 `0`、40101 应填 `100`；
     取值范围 0~65535，数量取值范围 1~125（功能码 0x03 的协议上限）。
   - 建议填写目标设备确实存在的寄存器，否则设备可能以异常响应作答（见下）。
3. 点击「开始」进行扫描，点击「停止」可随时中断。

## 扫描行为说明

- 扫描按地址从小到大进行，**一旦发现第一个有响应的地址即停止扫描并弹窗提示**，
  不会输出完整的地址列表，也不提供响应时间统计（仅记录本次扫描总耗时）。
- 地址 0 为广播地址（从机按规范不应答），248~255 为保留地址，因此不参与扫描。
- 判定「有响应」包括两种情况：
  1. 正常读取到寄存器数据；
  2. 从机返回**异常响应**（功能码 | 0x80，如异常码 0x02 表示非法数据地址）。
     异常响应是一个带合法 CRC 的完整应答，说明该从机真实存在，只是拒绝了本次请求。
     此时日志会记录 `✅ 地址 X 存在（从机返回异常码 0x0X）`。
- 只有读超时、CRC 校验失败等情况才判定为无响应。

> 提示：若扫描结果提示「未找到有效地址」，请优先确认寄存器起始地址是否为目标设备
> 实际存在的地址，以及串口参数、接线（A/B 线）是否正确。

## 性能说明

- 读超时按波特率自动估算（最坏 256 字节帧长 × 11 位 + 200ms 处理余量，
  下限 300ms、上限 2000ms）：9600 bps 为 493ms，19200 bps 为 347ms，
  38400 bps 及以上为 300ms。
- 最坏情况（总线上没有任何设备应答）扫描耗时约为：9600 bps 约 120 秒，
  115200 bps 约 75 秒。
- 扫描期间每 50 个地址输出一次进度日志，避免逐条刷屏拖慢界面。

## 已知限制

- 只报告首个有响应的从机地址，不会一次列出总线上所有在线从机。
- 要求目标设备至少支持功能码 0x03（读取保持寄存器）。
- 尚未支持 Modbus TCP。

## 依赖与目标框架

| 包 | 版本 | 说明 |
| --- | --- | --- |
| [NModbus4](https://www.nuget.org/packages/NModbus4) | 2.1.0 | Modbus 主站实现，仅提供 .NET Framework 资产，构建时会出现 NU1701 回退告警 |
| [System.IO.Ports](https://www.nuget.org/packages/System.IO.Ports) | 6.0.0 | .NET 6 下的串口实现 |

- 目标框架：`net6.0-windows`。**.NET 6 已于 2024-11 停止支持**，构建会出现 NETSDK1138
  告警且不再获得安全更新，建议升级到 .NET 8。
- 长期维护建议迁移到官方后继包 **NModbus 3.x**（提供 netstandard2.0 资产，可被 .NET 6+ 原生引用）。

## 运行环境

- Windows
- .NET 6 Desktop Runtime 或更高版本的 .NET Desktop Runtime
